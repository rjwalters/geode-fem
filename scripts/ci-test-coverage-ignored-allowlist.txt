# Read by scripts/ci-test-coverage.py. Running a target's default tier does
# not run its #[ignore]d tests, so the guard lists every ignored test of
# every target that CI runs, and fails when
#   * an ignored test runs in no workflow (no `-- --ignored` /
#     `-- --include-ignored` command that selects it) and is NOT listed
#     here, or
#   * an entry here is stale: the test now runs, no longer exists, or its
#     target does not run in CI at all (that belongs in
#     ci-test-coverage-allowlist.txt), or
#   * an entry has no reason.
#
# Issue #793 timed every such test in release on ubuntu-latest (one test at
# a time, 20-min cap) and wired the passing ones into integration-tests.yml
# and arpack.yml. Every entry left here carries its reason. Shrink this
# file; do not grow it without a reason.
#
# Format: <crate>/<target>::<test>  # <reason>   (one ignored test), or
#         <crate>/<target>  # <reason>           (every ignored test of the
#                                                 target). The reason is
#         required, on the same line.
#
# Unit tests (issue #921): a crate's `--lib` target is <crate>/lib, and its
# tests are named by module path, for example

# The dense reference tier of the two Silver-Müller self-consistent targets
# (issue #917). Each test runs 10 to 31 full dense solves of the 4512-DOF
# pencil (FaerComplexEigensolver, a complete complex Schur decomposition
# per solve, with eigenvectors in the vector-tracking target), which does
# not fit a 45-min job. Measured 2026-10-07 on origin/main, release, local
# 28-core host at load 65-200, three tests in parallel:
# silvermuller_self_consistent 39 min (3 passed),
# silvermuller_self_consistent_vector_tracking 38 min (2 passed, 1 failed).
# CI runs the targets' default tier instead (the sparse_* tests,
# integration-tests.yml core-dense-eigen): the self-consistent drivers on
# the sparse complex Lanczos, from the dense tier's seed eigenvalues, in
# about 2 min. That tier checks its seeds and windows against a dense
# solve. It is NOT the same scenarios: the dense tier picks by frozen
# index, the sparse tier by nearest eigenvalue (which is not the same
# eigenvector) or by eigenvector overlap inside a 12-pair window. Of five
# runs, two end where the dense run ends (seed k0 = 1, first mode, with and
# without vector tracking) and three do not (seed k0 = 20; the second seed
# at k0 = 1, where the nearest-eigenvalue pick changes eigenvector four
# times; mode death at k0 = 25). Each sparse test pins its own outcome and
# says where it differs. So the dense assertions below are not exercised
# in CI by an equivalent test, only by related ones.
# vector_tracked_beats_frozen_int_idx was re-seeded at k0 = 20 by issue #940
# (it failed from k0 = 1, where both drivers follow the same Silver-Müller
# mode). It now passes, measured at 126 min (49 dense solves with 1104
# eigenvectors each, load 110-130). The resonance it converges on runs in CI
# as sparse_vector_tracked_converges_on_sphere_resonance, and the
# comparison as synthetic_vector_tracked_beats_frozen_int_idx.

geode-core/silvermuller_self_consistent_vector_tracking::vector_tracked_converges_on_lowest_mode  # dense reference tier: ~38 min for the target; sparse_vector_tracked_converges_on_lowest_mode runs in CI (#917)
geode-core/silvermuller_self_consistent_vector_tracking::vector_tracked_handles_mode_death  # dense reference tier: ~38 min for the target; sparse_vector_tracked_handles_mode_death runs in CI from the same seed and ends on ModeLost, not the dense MaxIterations (#917)
