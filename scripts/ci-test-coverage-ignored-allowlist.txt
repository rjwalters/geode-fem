# #[ignore]d tests that no CI workflow runs (issue #793).

# Read by scripts/ci-test-coverage.py. Running a target's default tier does
# not run its #[ignore]d tests, so the guard lists every ignored test of
# every target that CI runs, and fails when
#   * an ignored test runs in no workflow (no `-- --ignored` /
#     `-- --include-ignored` command that selects it) and is NOT listed
#     here, or
#   * an entry here is stale: the test now runs, no longer exists, or its
#     target does not run in CI at all (that belongs in
#     ci-test-coverage-allowlist.txt), or
#   * an entry has no reason.
#
# Issue #793 timed every such test in release on ubuntu-latest (one test at
# a time, 20-min cap) and wired the passing ones into integration-tests.yml
# and arpack.yml. Every entry left here carries its reason. Shrink this
# file; do not grow it without a reason.
#
# Format: <crate>/<target>::<test>  # <reason>   (one ignored test), or
#         <crate>/<target>  # <reason>           (every ignored test of the
#                                                 target). The reason is
#         required, on the same line.
#
# Unit tests (issue #921): a crate's `--lib` target is <crate>/lib, and its
# tests are named by module path, for example
#   geode-core/lib::driven::solve::tests::some_benchmark  # <reason>
# No lib entry is needed today: #921 timed the four #[ignore]d geode-core
# unit tests in release (0.7 s to 14.7 s each, local Apple M3 Ultra) and
# arpack.yml runs all four by name.
