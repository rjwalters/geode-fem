# `benchmarks/transmon_devicelayout_optimize/` — DeviceLayout.jl SingleTransmon re-optimization (#1092 part 2)

DeviceLayout.jl's SingleTransmon example tunes two parameters, the transmon
`capacitor_length` and the readout resonator `total_length`, toward
`targets_GHz = [3.0, 4.0]` (`run_optimization` in the example source; the
blog does not state the targets). It uses PRIMA (derivative-free) in the
variables `x1 = √(620 µm / c)`, `x2 = 5000 µm / L`, with box `[0.6, 1.4]²`.
It stops when `Σ (f − t)² / t² / 2 < 1e-4` and reports 9 Palace runs to
`c = 1217.678 µm`, `L = 7243.955 µm` at `[3.005, 3.982]` GHz.

This benchmark repeats that optimization with geode's gradient, against two
objectives:

1. **DeviceLayout's own discretization.** This is the comparison with PRIMA:
   Palace on DeviceLayout's mesh_order 2 mesh at solver_order 2, with the
   example's `configfile` verbatim.
2. **The converged frequencies** (part 1 shows DeviceLayout's discretization
   sits 6–8 % below them on the qubit).

## Method

- **`capacitor_length`: shape gradient.**
  - **The motion.** DeviceLayout keeps the junction at the origin and builds
    the island up from y = 12 µm. Everything above the island translates
    rigidly with c, and the box re-centers by c/2 (checked on the part-1
    meshes). `examples/transmon_devicelayout_optimize.rs` turns that motion
    into a node velocity ∂X/∂c.
  - **The mesh check.** Before using the velocity, the example verifies on
    the mesh that every metal outline node in a stretched or blended band
    lies on an edge the motion maps onto itself.
  - **The gradient.** The adjoint-free Hellmann–Feynman contraction
    `EigenSensitivity::deigenvalue_dtheta_tensor_eps` (new; sapphire tensor
    through the exact full-tensor element JVP) takes 0.4 s per solve. On the
    initial mesh it matches a central difference of two re-solves of the
    moved mesh to every printed digit.
- **`total_length`: transmission line.** DeviceLayout re-lays the meander when
  L changes, so no fixed-topology node motion represents it.
  - f_r (L + δ) is constant, with δ from one finite difference of two
    DeviceLayout meshes (L = 5000 → 5250 µm).
  - ∂f_q/∂L = 0, because the physical dressing shift is about 1e-6 GHz/µm.
- **Why Newton runs on the high-fidelity objective.** DeviceLayout re-meshes
  every design, so the order-1 objective is not smooth in the parameters. A
  30 µm change of c moves f_q by more than twice what the fixed-topology
  derivative predicts, and a 250 µm change of L moves f_q by 1.4 %.
  - So there is no inner optimization on the cheap solves.
  - Newton runs directly on the high-fidelity objective, in DeviceLayout's
    variables x1, x2. Its Jacobian is geode's gradient scaled by the
    measured fidelity ratio S = F / f_h at the same design.
  - Each step costs one geode order-1 solve with its gradient (about 35 s)
    and one high-fidelity evaluation.

## Files

- `results.toml`: the artifact (MANIFEST bucket A), written by
  `cargo run -p geode-core --release --example transmon_devicelayout_optimize`
  (assemble mode). Pinned by `tests/transmon_devicelayout_optimize.rs`.
- `runs/`: geode solve records with gradients, one per evaluation. They are
  written by the same example in solve mode on the worker, via `driver.py`.
- `opt_log.jsonl`: the driver's log of every evaluation and step.
- `driver.py`, `ladder.sh`, `worker_ladder.sh`: the orchestration. Meshes are
  generated by DeviceLayout on the host with Julia, and the solves run on the
  AWS worker.
- `ladder_<tag>/`: geode records, logs and mesh sha256 of the verification
  ladders.
- `logs/`, `reports/`: solve logs, `time -v` records, per-design generator
  reports and mesh sha256.
- Palace cells: `reference/fixtures/transmon_palace/results_optimize_1092/`.
