# benchmarks/

Committed results for the GEODE-FEM benchmark suite, one subdirectory per
benchmark family. Most files are `results*.toml` written by an example binary
or a `--ignored` release-tier test, and the header of each file names the
command that regenerates it and the test that reads it. The tests compare a
fresh solve against these numbers within documented tolerance bands, or skip
with a note when an external oracle such as Palace has not been run. Files
marked "Auto-generated" must not be edited by hand: regenerate them after an
intentional change and commit the new file with the code change.

| [`transmon_bench_cpu/`](transmon_bench_cpu/) | geode-vs-Palace CPU timing and memory on the same transmon mesh; performance record only, not a CI gate. Four files. `results.toml` is the 2026-07-14 EC2 session: both solvers were given the same request, no mode log was kept, and its "1 thread" rows were not pinned (#927, #763; each cell now points at its re-measurement). [`results_like_for_like_m6i.toml`](transmon_bench_cpu/results_like_for_like_m6i.toml) is the 2026-10-08 same-box re-timing on an m6i.4xlarge with every mode list committed and one-thread runs pinned by the OS: the historical request returns 1 of Palace's 6 modes, and three geode requests that return all six (30 modes at 4.5 GHz; 6 modes at 20 GHz; 8 modes at 4.5 GHz with the port-aware projection) are reported beside Palace at 1 and 8 wide, in wall seconds and core-seconds. Two of the three were tuned against the Palace answer and the third still returns two non-physical modes (#950); no winner is declared. [`results_tuned_palace_m6i.toml`](transmon_bench_cpu/results_tuned_palace_m6i.toml) re-times Palace from a tuned recipe (libxsmm, `-march=icelake-server`, host-built single-threaded OpenBLAS; `reference/palace/docker/Dockerfile.tuned`) on one m6i.4xlarge, with the untuned recipe rebuilt and timed on the same box as a control and the same geode requests re-run beside it: on one box the tuned build is 1.2% to 4.5% faster, less than the 3.8% to 6.0% by which the untuned recipe differs between two m6i instances; side-by-side table in the directory's [README](transmon_bench_cpu/README.md). [`results_like_for_like_local.toml`](transmon_bench_cpu/results_like_for_like_local.toml) is the earlier geode-only dev-machine record of which requests return the six modes; its times are not comparable with the EC2 cells | `results.toml`: measured on EC2; see the file header. `results_like_for_like_m6i.toml`: `m6i_box_setup.sh` then `m6i_box_bench.sh` on the box, then `summarize_like_for_like_m6i.py` over [the run tree](transmon_bench_cpu/runs/2026-10-08_m6i_like_for_like/README.md). `results_tuned_palace_m6i.toml`: `m6i_tuned_box_setup.sh` then `m6i_tuned_box_bench.sh` on the box, then `summarize_tuned_palace_m6i.py` over [the run tree](transmon_bench_cpu/runs/2026-10-09_m6i_tuned_palace/README.md) and the PR #964 tree. `results_like_for_like_local.toml`: `like_for_like_local.sh`, then `summarize_like_for_like.py` |
