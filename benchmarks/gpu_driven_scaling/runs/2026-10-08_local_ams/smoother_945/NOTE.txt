Before / after measurement for issue #945 (the AMS V-cycle's damped-Jacobi edge
smoother used a fixed weight 0.6, above the stability bound on this fixture).
Summarized as [smoother_weight] of results_ams_cpu_local.toml.

Developer machine, single samples. The 1-minute load average was 6 to 21 on 28
logical CPUs during these runs, far lower than during the #930 and #946
sessions, but other work was running. Iteration counts are the result.
process user + sys seconds are the cost figure; wall-clock times are recorded
and not compared between legs.

Builds
  main   origin/main 61e8571e (the merge of PR #957), clean checkout, own target
         directory. Weight fixed at 0.6.
  fix    branch commit 11d1d60c, clean. The weight is chosen per preconditioner
         build: 0.6 if 0.6 * theta < 2, else 1.5 / min(1.1 * theta, gershgorin),
         theta being the largest Ritz value of 30 Lanczos steps on
         D^-1/2 P D^-1/2.
  w060   the fix build with GEODE_AMS_SMOOTH_WEIGHT=0.6, i.e. the old weight.
         main has no GEODE_SCALING_OMEGA knob (the branch adds it), so this is
         the "before" at omega = 0.05 and 0.20. At omega = 0.10 both main and
         w060 were run: they agree in iteration count, residual and port
         voltage to every printed digit at all six sizes
         (main_equals_forced_0p6 in the TOML).

11d1d60c is the first commit of the branch and holds every code change. Later
commits add this record, the summarizer section, documentation and comments;
they do not change the solver, so the trees were not rerun.

Sweep trees (ams_cpu_sweep.sh, sizes 6 9 12 15 20 24, one process per leg)
  main_w0p10         main, omega 0.10, SKIP_DIRECT=1
  fix_w0p10          fix, omega 0.10, all four legs (direct, jacobi, ams, xcheck)
  w060_w0p10         w060, omega 0.10, SKIP_DIRECT=1
  fix_w0p10_rayon1   fix, omega 0.10, RAYON_NUM_THREADS=1, SKIP_DIRECT=1
  fix_w0p05          fix, GEODE_SCALING_OMEGA=0.05, all four legs
  w060_w0p05         w060, GEODE_SCALING_OMEGA=0.05, SKIP_DIRECT=1
  fix_w0p20          fix, GEODE_SCALING_OMEGA=0.20, all four legs
  w060_w0p20         w060, GEODE_SCALING_OMEGA=0.20, SKIP_DIRECT=1
Run in that order.

Each AMS leg's .err carries one "# ams_smoother ..." line (the fix build
prints it under GEODE_AMS_SMOOTH_REPORT, which ams_cpu_sweep.sh sets): the
Ritz value theta_max, the Gershgorin bound, rho_hat = min(1.1 * theta,
gershgorin), the weight, its source, and estimate_ms, the wall clock of the
Gershgorin pass plus the 30-step Lanczos run. main prints no such line.

The main tree was written by main's copy of ams_cpu_sweep.sh, so its .meta
files lack the scaling_omega / ams_smooth_weight lines the branch's script
adds. The script's build.log is not kept (it holds machine paths).

ritz_gap/w0p05, w0p10, w0p20 (.stdout, .err)
  How far the 30-step Ritz value is below a converged one. One process per
  frequency, all six sizes, the fix build with GEODE_AMS_SMOOTH_REPORT=1000:
  each build then also runs 1000 Lanczos steps from the same start vector and
  prints theta_ref. Both are lower bounds on lambda_max; the 1000-step value
  agrees with the 2000-step power iteration of diagnostics/sw_rho.stdout to the
  digits printed there (3.38761 at n = 6). The setup times in these .stdout
  files include the 1000 extra operator applies and are not used.
    GEODE_AMS_SMOOTH_REPORT=1000 GEODE_SCALING_OMEGA=<w> \
    GEODE_SCALING_SIZES=6,9,12,15,20,24 GEODE_SCALING_CONFIGS=iterative_ams \
    GEODE_SCALING_REPS=0 GEODE_SCALING_SKIP_E2E=1 GEODE_SCALING_SKIP_SWEEP=1 \
    GEODE_SCALING_SPLIT_SETUP=1 cargo test -p geode-core --release \
    --test gpu_driven_scaling -- --ignored --nocapture

  Only the spiral_golden and anisotropic_golden tests pass the child's
  "# ams_smoother" lines through on success, so spiral_ds, spiral_drude and
  rough have no smoother entries. They use the spiral_smoke mesh.

  spiral_aniso was added after the others and run by hand with the same
  header: main at 61e8571e, fix at e07237e5 (11d1d60c plus this record and a
  test-only change that prints the smoother lines; no solver change). It is
  the one test outside the cube fixture where the weight is lowered: at 1 GHz
  theta = 3.4297, so 0.6 is proven above the bound, the weight becomes 0.398,
  and the solve takes 118 iterations where main takes 114. At 10 GHz the
  weight stays 0.6 and the count stays 148.

  spiral_debye fails on both trees in the same way (issue #943): it is not a
  result of this change and was not altered.

  transmon_real fails on both trees before its AMS leg starts: the Jacobi
  eigensolve it runs first stops at a relative residual of 0.69 after 266 216
  inner iterations (about 18 minutes). So that test gives no AMS number on
  either tree. The main and fix runs overlapped in time (the fix run was
  started by hand while the main run was still going).

  fix_transmon_real_ams_only.txt, .time
    The AMS leg alone, by a throwaway test added to the fix build
    (diag945_real_transmon_ams_only.patch: test code only, no solver change;
    applied, run once, reverted). It was STOPPED BY HAND after 37 minutes
    (2 237 s of user time) without finishing, which is why the .time file
    says "terminated abnormally" and there is no iteration count. What it
    does record is the smoother line of the 133k-DOF build: theta = 2.9434
    (600-step reference 2.9434), Gershgorin 4.53, weight 0.6, source
    "default". The weight is unchanged from main on this fixture, so the AMS
    eigensolve is the one main runs; how long that takes was not established.
